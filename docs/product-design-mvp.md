# MVP 产品需求与设计方案：个人经验型桌面助手（dsh-mem）

日期：2026-09-21 ｜ 状态：MVP 需求草案 v1，待评审
依据：《个人经验型桌面AI助手-产品方向评估-2026-09-21.md》（下称「评估」）、《产品方向对话记录_2026-09-20.md》、《HANDOFF-2026-09-20.md》（dsh-look 工程现状）

---

## 1. 一句话定位

> 一个随手可用的桌面 AI 助手：在当前注意力位置召唤、就地回答，并把共同解决问题的经历沉淀为**带来源、可纠正、有适用条件**的问题案例，让下一次相似任务少解释一次背景、少重做一次研究、少踩一次已经踩过的坑。

用户价值口径（对外表述）：**少解释一次背景，少重做一次研究，少踩一次已经踩过的坑。**

## 2. 背景与已确定的方向决策

- 长期资产承载从「农场/收菜」转向「个人经验（问题案例）」：积累物与真实工作价值同源，成长可具体可查（评估 §1、§2）；
- 保留三个交互约束：**在当前注意力位置召唤和交付；使用成熟模型与 Agent 运行框架（不从零造 Harness）；默认不要求用户逐次验收或维护笔记**；
- 架构通用，但第一版聚焦：**一个平台（macOS）、一个轻量入口（已有气泡+热键）、一个主要工作来源、一个项目**；
- 农场/桌宠/皮肤/三维空间/全时录屏全部后置（评估 §2、§10），不进 MVP。

## 3. 目标用户与首发场景

**首批用户画像**：已有高频 AI 使用习惯、跨应用工作、项目持续数周且会重复解释背景的人——**首发锁定一个群体：产品经理/研究员（即作者本人 + 3–5 名同类同事）**。选这个群体不是因为模型只能处理它，而是便于观察相同形态的问题（评估 §10）。

**首发工作来源**：Chrome 页面 + 原生 App 的选中文本 / 用户主动粘贴的内容（即 dsh-look M0+M3 已覆盖的 AX 通路）。微信气泡等 AX 盲区等 M4 OCR 落地后再纳入。

**首发项目（示例）**：求职材料准备、一个持续的产品方向调研项目。用户自选一个项目 + 3–5 段历史案例作为冷启动起点。

## 4. 目标与非目标

### 4.1 MVP 目标（对应评估 §10 六项能力）

| # | 能力 | 一句话验收口径 |
|---|---|---|
| C1 | 明确召唤，就地回答 | 热键召唤即捕获当前上下文，答案锚定在光标/选区旁，不强迫进入主窗口 |
| C2 | 带来源的问题案例 | 任务后自动生成案例卡片，引用可回溯到来源（窗口标题/URL/选中文本/时间） |
| C3 | 经验候选抽取 | 从案例中抽取少量决策/方法候选，去重并挂到项目，默认是「候选」不是「事实」 |
| C4 | 新任务召回 | 新任务中带回少量相关旧案例，显示来源与「为何相关」，直接协助产出 |
| C5 | 纠正与删除生效 | 用户可纠正、忽略、删除任何经验；更正影响下一次召回 |
| C6 | 书架视图 | 一个简洁视图展示少量真实案例及其复用/修订过程 |

### 4.2 非目标（明确不做）

- 农场、皮肤商店、桌宠人格、三维空间、记忆宫殿布局；
- 全时录屏/全天监控（坚持拉模型：只在召唤时读取）；
- 自动执行类技能（改文件、外发消息）——保持只读辅助定位；
- 多平台、多项目并发的权限体系（单项目简化处理）；
- 图数据库、复杂知识图谱（评估 §7：结构化存储 + Markdown + 可重建索引即可）。

## 5. 核心用户故事（验收即剧本）

**US-1 就地回答**：我在 Chrome 看一份英文合同，按 ⌥⌘Z，问「这条有什么风险」——气泡在光标旁出现答案，引用了我正在看的页面标题和那段选中文本。全程没有离开 Chrome。

**US-2 案例沉淀**：昨天那次「为什么选 Markdown 而不是图数据库存储」的讨论，今天在书架视图里看到一张案例卡：问题、当时看到的证据、尝试过的选项、最后的选择、理由——每一条都带来源。结果栏标注「未知（尚无上线证据）」，系统没有编造结果。

**US-3 带条件复用（最有辨识度的瞬间，评估 §3）**：两周后我在新项目里考虑类似选型，召唤助手问存储方案。它回答：「上次你选了 Markdown+结构化索引，理由是索引可重建；但那次的前提是单机单人，这次有多端同步需求，这个条件可能不成立，建议重新评估。」并附上旧案例链接。

**US-4 纠正生效**：助手把一条我否掉过的方案当成「我的偏好」召回了。我点「这不代表我的偏好，本次忽略历史」——下次同类任务不再出现这条，且案例里记录了这次纠正的时间和原因。

**US-5 删除彻底**：我删除一条案例，它的摘要、索引、被引用它的经验候选同步失效；书架上的引用显示「来源已删除」而不是残留编造内容。

## 6. MVP 对象模型（评估 §7 的裁剪版）

MVP 只做 5 类对象（完整模型中 Attempt/Outcome 折叠进 Case 字段，Decision 折叠进 Claim 的来源链）：

```
Project（项目） 1 ─ n Case（问题案例）
Case 1 ─ n Source（来源）
Case 1 ─ n Claim（经验候选）
Claim n ─ 1 Project
```

| 对象 | MVP 最小字段 | 关键规则 |
|---|---|---|
| Project | id、名称、状态、创建时间 | 冷启动由用户显式创建，唯一 |
| Case | id、projectId、问题陈述、约束、状态(open/resolved/unknown)、尝试与选择摘要、结果(known/unknown/partial)、发生时间、记录时间 | 跨会话持续；**无结果证据时如实标注 unknown** |
| Source | id、类型(app/ax-selection/paste/file)、窗口标题/URL、片段定位、抓取时间、原文摘录 | 被「读取」≠ 被「用户认可」，单独标记 |
| Claim | id、caseId、projectId、结论、证据状态(用户确认/推断/待核实)、适用条件、反例、状态(候选/生效/失效/被替代)、版本 | 默认候选；升级为「生效」需用户确认或多次验证 |
| 全对象公共 | 稳定 id、来源链、版本、替代关系(supersededBy)、保留策略 | 删除需级联到索引与引用（C5） |

**证据状态只用明确类别**（原文记录/用户明确决定/工具结果/推断/待核实），不用置信度百分比。
**区分四个行为**：用户分享过 / AI 检索到 / 内容曾显示在屏幕上 / 用户明确认可——系统不得因「出现在窗口中」声称「用户读过」。

## 7. 交互设计

### 7.1 入口与交付（复用已验收工程）

- **召唤**：⌥⌘Z（M2-lite 已验收：召唤瞬间抓快照，焦点未丢、选区最完整，挂 pre-step 隐藏注入，TTL 5min）。P1 语音（按住说话）作为第二入口，**不阻塞 MVP 主链路**，随排期合入；
- **交付**：答案在气泡内就地渲染（光标/选区锚定）；复杂内容可展开为对话框；
- **采集可见**：气泡顶部显示本次捕获的上下文摘要（「已读取：Chrome × XX页面 + 选中文本 143 字」），可手动清除——这是对「全天监控」疑虑的直接回答。

### 7.2 沉淀（默认自动、可选确认）

- 任务结束后后台生成案例候选，**不打断**；气泡收起前给一条轻提示「已留下 1 条案例」，点击可看；
- 抽取 0–3 条 Claim 候选/案例，自动去重挂项目；
- 事实冲突、归属不明、高影响规则才进「需注意队列」（评估 §5）；其余作为带标签线索存在，不静默升级为事实。

### 7.3 召回（新任务中）

- 检索触发：新任务的快照+问题里命中旧案例的项目/主题/条件；
- 召回展示三要素：**旧案例摘要 + 为何相关 + 适用条件提示**；权限/项目/时间先过滤；
- 明确区分「引用旧材料」与「新判断」；回答里旧经验以引用块出现；
- 保留三个逃生口：**本次忽略历史 / 重新从证据判断 / 这不代表我的长期偏好**（评估 §8）。

### 7.4 书架视图（C6）

- 一个只读优先的简洁界面（MVP 可为一个本地 Web 页或 DSH 展开窗内的 tab）；
- 按项目分组，展示案例卡（问题→选择→结果→复用记录）；被复用过的案例有「复用 ×N」标记和最近一次复用链接；
- 每张卡可进入：纠正结论、补充反例、标记失效、删除。

## 8. 技术方案（基于现有 DSH 工程）

### 8.1 总体

新增 DSH 插件 `dsh-mem`（与 dsh-look 同构：`file:`/`link:` 协议挂入 `~/.dsh/profiles/desktop`），复用 DSH Host 的 agent 运行时与 skill 机制。**不从零建 Agent 平台，增量补链路**（评估 §12）。

```
dsh-look（已有）                    dsh-mem（新建）
  look 快照 ──pre-step 注入──→  agent 回答（就地交付）
                                  │
                    ┌─────────────┼──────────────┐
                 会话结束钩子            新任务 pre-step
                    ↓                      ↓
              案例抽取（LLM）        案例检索（本地索引）
                    ↓                      ↓
              Claim 候选抽取      召回注入（带条件提示）
                    ↓
              本地存储 + 索引
```

### 8.2 存储（评估 §7 的落地）

- **结构化状态**：SQLite（或 JSONL 起步）存 5 类对象及关系边；每条边带证据、时间、推断状态；
- **可读内容**：案例正文以 Markdown 存（`~/<vault>/cases/<id>.md`，frontmatter 放结构化字段）；
- **索引可重建**：全文/向量索引是派生物，删源即删索引，不作为唯一事实源；
- 预留与 Obsidian 的边界约定（唯一事实源 + 写入白名单），MVP 不接。

### 8.3 关键管线

1. **案例抽取**（会话结束/pre-step 收尾）：输入=本次对话+快照来源；输出=Case+Source 候选；提示词强制「无结果证据标 unknown，不得补写结果」；
2. **Claim 抽取**：每案例 ≤3 条，必须带适用条件；与既有 Claim 做相似去重（命中则版本递增而非新建）；
3. **召回**：新任务 pre-step 阶段，用快照+问题检索（MVP 用关键词+本地向量即可），top-k≤3，附带适用条件比对（时间/项目/工具版本变化则降权并提示）；
4. **纠正回写**：用户在书架/召回卡片上的操作直接更新对象状态，并写入事件流（谁、何时、为何改）。

### 8.4 与既有排期的关系

| 既有事项 | MVP 关系 |
|---|---|
| M4 截图+OCR | **非阻塞**（首发来源避开 AX 盲区），P1 优先级让位本方案主链路 |
| P1 语音衔接 | 第二召唤入口，可并行，不阻塞 |
| 快照 UI 化（P2） | 被 7.1「采集可见」提示条吸收，随 MVP 实现 |

## 9. 里程碑与验收（沿用 ACCEPTANCE-M0 风格）

| 阶段 | 交付 | 验收判据（全部可脚本化复测） |
|---|---|---|
| **M-mem-1 就地闭环** | C1 + 采集可见提示 | E1：Chrome 选中文本 → ⌥⌘Z → 提问 → 答案含选区内容且气泡就地渲染；提示条正确显示捕获范围 |
| **M-mem-2 案例沉淀** | C2 + C3 | E2：一次真实任务后 60s 内生成 Case，Source 回溯到窗口标题/URL/时间；无结果时结果=unknown；Claim ≤3 且带适用条件 |
| **M-mem-3 复用闭环** | C4 | E3（核心）：同项目新任务提问，召回旧案例，回答含「旧选择+理由+条件变化提示」三要素，引用可点开原案例 |
| **M-mem-4 纠正生效** | C5 | E4：删除 Case 后索引与引用同步失效（重启后不复现）；「忽略历史」后同类召回不再出现；纠正写入事件流 |
| **M-mem-5 书架** | C6 | E5：书架按项目展示案例卡+复用标记；支持纠正/失效/删除操作 |

**端到端北极星验收**：本人真实使用两周后，出现 ≥3 次「US-3 式」带条件复用（可指出来源、进入的任务、帮助依据），维护中位数 ≤5 分钟/周。

## 10. 指标与验证（评估 §11 的 MVP 裁剪）

- **北极星**：每周被验证对当前工作有帮助的经验复用次数（复用需可指出：来源案例+进入的任务+帮助依据；复制/点击只算代理信号）；
- 辅助：首次有效复用时间（目标 7 天内）、维护负担（≤5min/周）、召回质量（误用/漏掉/合理不调用分别统计）、删除残留（必须为 0，出现即 P0 修复）；
- 对照基线（小型 A/B，n=自己+3–5 同事）：只有当前上下文 vs 可检索原始聊天记录 vs 结构化案例——**后两者差异才证明整理值得**（评估 §11B）；
- 停止条件：若「原始聊天可检索」基线已表现足够好，不投入更复杂图谱；若维护负担压不住，先收窄采集范围而不是加提醒。

## 11. 信任与隐私边界（直接决定用户敢不敢常驻桌面）

| 风险 | MVP 处理 |
|---|---|
| 全天监控疑虑 | 拉模型+零轮询（继承 dsh-look 架构）+ 采集可见提示条 + 召唤才有快照 |
| AI 猜测变成个人事实 | 证据状态显式分类；推断永远可识别、可纠正 |
| 项目/私人材料串用 | 单项目起步，检索按 projectId 先过滤 |
| 删除不彻底 | 删除级联（对象→索引→引用），E4 验收覆盖，残留=0 硬指标 |
| 历史内容注入指令 | 来源即数据：旧案例文本不授予任何行动权限（与只读定位双保险） |
| 服务退出记忆不可用 | 本地 Markdown+SQLite，天然可导出离线阅读 |

## 12. 开放问题（进 MVP 评审议程）

1. 「复用」的判定埋点精确定义（引用被采纳？回答后无手动重做？需抽样回访校准）；
2. 书架视图放 DSH 展开窗内 tab 还是独立本地页面；
3. Claim 相似去重的阈值与「版本递增 vs 新建」边界；
4. 召回注入的位置（pre-step 隐藏 vs 显式引用块）对回答质量的影响；
5. P1 语音与 M4 OCR 的插入时机（当前建议：主链路 M-mem-1→5 之后）。
